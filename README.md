# LucX-UI (форк gotyefrid)

Форк панели [AlexeyLCP/lucx-ui](https://github.com/AlexeyLCP/lucx-ui), которая сама построена на [3x-ui](https://github.com/MHSanaei/3x-ui).

**Всё как в оригинале**: протоколы Xray, AmneziaWG, туннельные сайдкары, подписки, Telegram-бот и остальное. Полное описание возможностей — в [README оригинала](https://github.com/AlexeyLCP/lucx-ui#readme). Ниже — только то, что добавлено или исправлено в этом форке.

> [!WARNING]
> Только для личного, некоммерческого, исследовательского и образовательного использования. Коммерческое использование, включая перепродажу VPN, требует письменного разрешения автора LucX-UI (лицензия PolyForm Noncommercial 1.0.0, см. [LICENSING.md](docs/LICENSING.md)).

## Установка

Одна команда на чистом Linux-сервере (Ubuntu, Debian, CentOS, AlmaLinux, Arch и др.), от root:

```bash
bash <(curl -fL https://raw.githubusercontent.com/gotyefrid/lucx-ui/main/install.sh)
```

Установщик скачивает последний релиз этого форка со всеми сайдкарами, собирает модуль ядра AmneziaWG и предлагает выпустить сертификат для панели. В конце он печатает адрес панели, логин и пароль и сохраняет их в `/etc/x-ui/install-result.env`. Этот файл заполняется один раз: если потом сменить пароль в панели, он не обновится.

Конкретная версия:

```bash
bash <(curl -fL https://raw.githubusercontent.com/gotyefrid/lucx-ui/main/install.sh) v3.11.0-lucx.358
```

Без вопросов (cloud-init, скрипты):

```bash
XUI_NONINTERACTIVE=1 bash <(curl -fL https://raw.githubusercontent.com/gotyefrid/lucx-ui/main/install.sh)
```

**Обновление** — команда `x-ui update` или кнопка обновления в панели. И то и другое берёт релизы этого форка, а не оригинала.

**Поверх оригинального LucX-UI или 3x-ui** — сначала сохраните базу, затем выполните ту же команду установки:

```bash
cp /etc/x-ui/x-ui.db /root/x-ui.db.bak
bash <(curl -fL https://raw.githubusercontent.com/gotyefrid/lucx-ui/main/install.sh)
```

> [!NOTE]
> Не используйте `--yandex`, Docker-образ `ghcr.io/alexeylcp/lucx-ui` и скрипт для Keenetic из оригинала: они ставят сборку оригинала без доработок форка.

## Перенос на другой сервер

1. На старом сервере: «Бэкап и восстановление» → «Экспорт базы данных». Скачается файл `.db`.
2. На новом сервере: установка командой выше.
3. В новой панели: «Бэкап и восстановление» → «Импорт базы данных».

В файл копии входят не только инбаунды и клиенты, но и состояние сайдкаров: пароли и ключи сервера wdtt, участники CSQTT, ключи aivpn, сертификаты Naive. Поэтому уже выданные клиентам конфиги продолжают работать на новом сервере без перевыпуска. Подробнее — ниже, в разделе «Резервная копия».

Что учесть:

- Файл копии содержит пароли, ключи и токен бота. Храните его как пароль.
- Логин и пароль панели после импорта становятся такими же, как на старом сервере.
- Если старый сервер продолжит работать, выключите Telegram-бота на одном из них. Два сервера с одним токеном мешают друг другу получать сообщения (ошибка `409 Conflict`).
- Сертификат панели и настройки системы (firewall, fail2ban) в копию не входят: их настраивает установщик.

## Что добавлено в форке

### wdtt (qWDTT): отдельный пароль на клиента

В оригинале у инбаунда qWDTT один общий пароль на всех. В форке у инбаунда есть опция **«Индивидуальные пароли»** (по умолчанию выключена, тогда все используют главный пароль):

- каждый клиент панели получает свой пароль на сервере wdtt, а ссылки `qwdtt://` и `wdtt://` содержат его пароль;
- включение и выключение клиента, срок действия и лимит трафика применяются к его паролю; лимит IP клиента задаёт лимит устройств;
- трафик и статус «в сети» считаются по подключениям этого пароля, а не по общему процессу;
- при переходе со старого wdtt существующие пароли подхватываются по метке, равной email клиента. Старые конфиги продолжают работать;
- сервер qWDTT пропатчен: лимит паролей поднят с 10 до 1000, статус «в сети» не путается между клиентами без device id.

### CSQTT: статистика по клиенту

- Трафик и статус «в сети» клиента берутся из счётчиков его участника на сервере CSQTT, а не из общего трафика процесса.
- Ошибка в настройках одного клиента не останавливает синхронизацию остальных.

### VK-звонок на клиента

- Для клиентов wdtt, CSQTT и iOS можно указать свой звонок VK. Если поле пустое, используется звонок инбаунда.
- Принимаются и хеши, и ссылки вида `https://vk.com/call/join/…`, через запятую.
- Поле есть в форме клиента в панели и в Telegram-боте.

### VK TURN для iOS

Новый тип инбаунда **VK TURN (iOS)**: релей [anton48/vk-turn-proxy](https://github.com/anton48/vk-turn-proxy) работает перед выбранным WireGuard-инбаундом.

- Клиенты — все клиенты этого WireGuard-инбаунда. Рядом с WireGuard-ссылкой им выдаётся `vkturnproxy://` для приложения vk-turn-proxy-ios: режим SRTP, ключи, адрес и звонок VK клиента.
- Статус релея виден в форме клиента, логи и бинарь — на странице ядер.

### Резервная копия

Экспорт базы кладёт в копию каталоги состояния сайдкаров (`bin/tunnel/*-data`), импорт возвращает их на место. Базы SQLite снимаются согласованно, даже если сайдкар работает. Без этого восстановленный сервер показывал клиентов в панели, но их конфиги wdtt и CSQTT не подключались.

### Telegram-бот

- При создании клиента и на карточке клиента можно задать VK-звонок.
- Ссылки и QR для клиентов wdtt и CSQTT открываются (раньше бот отвечал ошибкой).
- Клиенты wdtt и CSQTT находятся в поиске и в списках. Карточка инбаунда показывает правильное число клиентов (раньше было 0).

### Прочие исправления

- Массовое включение и выключение работает для клиентов wdtt, CSQTT и Telegram WEB proxy.
- Статистика клиента сайдкаров (qWDTT, CSQTT, olcRTC и др.) сохраняется при переименовании клиента.
- Установка, `x-ui update` и проверка обновлений в панели берут релизы этого форка. Источник можно сменить переменной `LUCX_REPO=owner/repo`.
